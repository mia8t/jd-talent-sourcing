# JD Talent Sourcing

**把岗位 JD 转化为可执行、可复用、可核验的人才寻访流程。**

面向招聘人员与支持 Skill 的 AI 助手：先确认岗位标准，再进行候选人召回、逐项证据核验、分级和授权写入，避免把关键词命中误当作岗位匹配。

## 核心能力

- **独立岗位 Prompt**：解析 JD、集中补缺、确认硬筛与软筛；不同岗位独立保存完整配置。
- **证据驱动筛选**：区分本人贡献、团队成果与关键词；缺少证据不默认通过。
- **分层寻访**：前置过滤、多组检索、详情核验、历史去重、A/B/C 分级。
- **可恢复执行**：区分列表召回、有效核验、合格、写入和回读；失败保持原批次进度。
- **授权与数据边界**：只在授权后写入结果，不默认锁定候选人、发送消息或改动招聘流程。

## 获取与使用

1. 从 [Releases](https://github.com/mia8t/jd-talent-sourcing/releases) 下载脱敏 ZIP，或下载本仓库源码。
2. 将 `jd-talent-sourcing/` 导入支持 `SKILL.md` 的助手环境。不同宿主的导入方式不同，本仓库不提供通用一键安装命令。
3. 在宿主中准备浏览器交互与飞书云文档能力，并由使用者完成登录和权限授权。
4. 提供 JD；确认岗位筛选规则、招聘平台配置、结果资源与执行范围后再运行。
5. 查看实际核验漏斗与结果回读，不以“打开页面”或“请求成功”作为完成证明。

需要宿主提供兼容 `browser` 和 `lark-doc` 的能力。本仓库仅声明依赖，不包含这些工具的实现、登录态或企业系统接口。没有相应能力时，需要自行适配，不保证可在任意助手中直接运行。

## 示例：全部虚构

以下仅演示任务输入，不是实际岗位或候选人信息：

> 为一项虚构的在线教育产品配置增长分析岗位。要求累计全职经验 2–4 年（不含实习），本人完成数据分析并推动实验落地；实验设计经验为加分项，地点不限。先输出完整筛选方案与待确认项，本轮只配置，不浏览人才库、不创建远程资源。

确认方案后，可另行授权：

> 按该岗位已确认方案有效核验 10 名独立候选人；只将全部硬筛通过且达到软筛门槛的候选人写入已授权结果文档，并逐批回读。未达目标如实报告，不放宽标准。

## 输出与数量口径

本公开版本使用 **飞书 Docx 原生 14 列结果表**，不是独立 Sheets 版本。

“找 N 份简历”默认指有效详情核验 N 人，**不等于保证推荐 N 人**；若希望合格结果达到指定人数，必须在岗位方案中单独确认目标与停止条件。

## 隐私与使用边界

- 本公开包不包含真实候选人材料、企业专属地址或筛选编码、账号凭证、远程资源绑定及既往运行记录。
- 企业平台地址、字段、评级规则和具体招聘政策由使用者在授权运行时配置，不随仓库分发。
- 真实简历、面评、截图与运行台账应保存于授权的运行资源，不提交到本仓库。
- 忽略规则不能替代发布前审查，也不会清除 Git 中已经提交的数据。
- 结构和逻辑验证不等于任意招聘系统上的端到端验收；页面变化、登录、权限或缺字段可能阻塞执行。
- 不保证发现足够的合格候选人，不把 AI 分级当作最终招聘决定。
