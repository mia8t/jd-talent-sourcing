# JD 人才寻访

本包只保存可复用的寻访流程、规则、代码示例和工具能力要求，不保存真实人员、组织、岗位绑定、登录配置或执行历史。招聘平台和云文档的地址、账号、范围及资源标识仅从使用者本轮授权配置取得，不随技能分发。结构验证不代替目标系统上的端到端验收。

## 首次使用入口

当用户仅加载或提及本 Skill，且尚未提供 JD、JD 文档来源或已配置岗位信息时，主动在对话框原样回复以下文本：

> 您可以输入目前正在sourcing的岗位JD或者告诉我读取哪些文档来获取岗位JD，我将会开始帮您完成人才sourcing的准备

已有 JD 或文档来源时直接读取解析，不重复欢迎；已有明确当前岗位配置时按下文再次启动规则处理，不反复索要 JD。未显式调用时按 description 匹配任务，不向无关请求插入欢迎话术。本入口是模型加载并遵循 Skill 时的文本引导，不是平台开场 UI 配置，不承诺任意模型仅收到文件名就自动加载。

## 能力、来源与授权

维护岗位 Prompt，并按最新确认版本随时寻访；一轮结束保留岗位就绪状态，不关闭岗位或删除配置。业务场景及组织范围来自使用者提供的 JD 或已确认岗位配置，未指定时仅补问影响执行的范围；不同岗位独立配置，不继承原作者或其他岗位的负责人、资源、账号与授权。历史优秀简历只扩展画像及检索词，不代替候选人证据。

可配置业务标准冲突按：本轮明确要求 → 当前岗位最新确认 Prompt → JD 原文 → 系统推断。此优先级不覆盖资源授权、所有锁定者不推荐、未知不算通过及写入回读闸门；有冲突停止受影响操作并说明。通用模板仅在新岗位初始化时用于集中确认，业务取值来自 JD 或使用者确认并标明来源，不重复补问已回答项。生成后每个岗位 Prompt 是独立、完整的业务配置快照；运行读取目标岗位最新确认版，不动态叠加基础默认。岗位“通用硬筛”改动只更新该岗位，不回写 Skill 或其他 Prompt；明确修改基础默认也不自动迁移已生成岗位。所有锁定者不推荐、未知不算通过、授权与回读等执行闸门仍不得绕过。

“必须、至少、不超过、不能”识别为硬门槛；“优先、熟悉、加分、最好”不自动升级。工作地点、量化 ROI/收入结果只有 JD/配置明确要求才设硬筛；学校范围及年限上下限按岗位要求，未设上限不新增。默认全职年限不含实习；明确例外记录计算方式。不能在后续阶段悄悄改口径。

首次完整方案明确确认可同时授权资源创建及本轮合格结果写入；只确认标准不等于授权创建或执行。确认前不改远程资源，授权后不逐人二次确认。显式只读运行不创建或修改任何远程资源（文档、元数据、记录、台账均包括），仅保存本地运行进度；另行配置维护授权不能推导只读运行可写。人工反馈只读学习，禁止覆盖删除。锁定、发消息需单独授权，本 Skill 默认不执行锁定，默认只在对话汇报。

## 首次配置：四步闭环

1. **输入 JD**：完整读取粘贴、链接或附件，提取岗位名称、业务问题/目标、关键动作、主责程度、可核验个人贡献、年限/实习口径、学历/第一学历/学校、必须背景、排除项、软实力及 AI。访问失败说明材料缺口，不凭摘要补全。
2. **形成完整方案**：生成可执行 Prompt，包含通用配置模板及已确认取值、H1～Hn 硬筛与证据、S1～Sn 软筛与 A/B/C 阈值、加分/反例、前置过滤能力、3～6 组关键词及轮次、详情顺序、正常目标/上限、去重/批次、文档绑定、写入与失败恢复。页面能力未核实标待验证。
3. **集中补缺**：来源状态标“默认已采用/JD 明确/用户已确认/系统建议/待确认冲突”。仅补问影响去留、分级或执行的关键缺口（经验证据、规则冲突、A/B 阈值、历史范围/负责人、目标与权限），给选项及影响；已回答原样承接，无缺口直接确认，不凑问题数量。
4. **补充并确认**：吸收回答形成同一份完整独立岗位 Prompt，按“岗位目标 → 通用硬筛 G → 个性化硬筛 H → 软筛 S/加分/分级 → 检索核验 → 输出/授权/停止”固定分区；标准逐条分行，写条件、核验证据、去留及来源，不让用户自行拼接对话或每次选择版式。完整格式、初始化快照和岗位隔离更新必须读 [独立岗位 Prompt 契约](references/role-prompt-contract.md)；确认展示表格与保存授权见结果参考。不能用执行步骤或 JD 摘要代替完整标准，正文不能动态引用 Skill 默认或聊天历史。四阶段不等于固定四条消息；新冲突只补问受影响项。授权创建后回读资源，在执行授权内开始，否则停在“资源已创建、待执行授权”。

每项能力映射 JD/用户来源、本人动作、直接负责/共同负责/深度参与口径、项目范围、结果、可接受证据和反例。团队目标转为待确认个人贡献要求；近义词不凑多项独立能力。“策略产品经验至少 2 年”仅为岗位要求示例，按已确认职责、有效经历和年限计算，不凭职位名，不推广为通用硬筛。

## 通用硬筛配置模板

以下保留各类筛选能力，不预置任何企业专属招聘政策。首次配置时从 JD 或使用者集中确认业务背景、意向有效期、学历、历史面评范围及判定条件，完整保存于独立岗位 Prompt；已有岗位运行沿用该岗位最新确认快照。

1. 按岗位明确要求核验公司背景或相关垂直经历，具体公司范围及经验门槛来自岗位配置，不将企业名称写入技能。
2. 在岗位确认的意向有效期内，备注明确拒绝机会者不推荐；有效期由使用者配置。确认相关备注已读取，空字段或读取失败不等于无拒绝。
3. 按岗位确认的学历、第一学历及学校范围核验；学校性质只在岗位明确要求时核查，陌生学校不凭名称猜测，不以更高学历补偿明确的第一学历硬门槛。
4. 所有锁定者不推荐；按目标系统经确认的可见锁定标志判断。只有姓名及状态区域完整加载、未锁状态的显示语义已核实，才可依据未出现锁定标志判断未锁；文本中没有“锁定”二字不单独证明未锁。不查预计解锁时间，不把接口 null 或未读状态当未锁，无法判明待核验。
5. 按当前岗位确认的历史流程、组织及负责人范围读取面评，使用已确认的评分、时间及组合条件判断，不在技能中预置任何企业的等级映射或淘汰政策。已完成面试但最终未推进的标注按岗位配置；影响结果的范围或规则未决时首次补问。
6. 历史重复按下文变化规则处理，禁止同批重复。
7. AI 默认加分，只有 JD/使用者明确要求才设硬筛；明确符合岗位 AI 标准才标 AI 优势。

可配置业务默认遇到明确岗位例外记录差异；执行闸门不能临时绕过。硬筛缺失、矛盾未解决或不通过不算满足；材料读不到待核验，不写合格记录，不以迁移能力、公司光环或加分补偿。

## 分层寻访与证据

**已支持硬条件标签且生效 → 多组关键词召回 → 列表初筛/本轮去重 → 详情状态/备注/面评 → 通用硬筛 → 完整简历/岗位硬筛 → 软筛/分级 → 历史变化核验 → 授权写入/回读。**

- 页面通用年限、学历等标签先设置验证；通用工作年限与 JD 限定经验分别核验，不要求相等。页面不能表达的条件留详情；已支持标签点击失败是前置阻塞，不能以“详情再查”跳过。不能以可选标签新增硬门槛，不逐一打开整个人才库。
- 先核验候选人稳定标识、当前锁定和可读材料，再读最近/相关备注、意向、投递/流程/负责人/终止原因、全部相关面评，最后独立审阅完整教育、工作、项目及必要附件。仅限制已确认相关范围，不无依据遍历无关历史，不只看摘要。过滤结果是否完整无法确认时标风险，不以可见列表冒充完整候选池。明确硬性淘汰可短路，记录实际已查/未查项与证据。
- 关键词仅召回；公司、职位、团队成果、优秀简历相似度不证明通过。证据强度与等级分开：E1=本人职责/动作/量化结果至少两维且满足该硬筛特定要求；E2=本人经历与动作明确但范围/结果不完整，仅硬筛允许时通过；E3=职位/关键词/团队成果/模糊描述，不能证明通过。学历、锁定、面评用直接状态证据，不强套项目贡献维度。
- 全部通用和岗位硬筛通过，独立软筛至少 1 项才可推荐；零项淘汰，加分不补最低门槛。A 达岗位已确认 A 条件，B 达 B 未达 A，C 至少 1 项但未达 A/B。A/B 阈值首次确认，执行时不猜；同一证据关联多要求须分别解释，不用近义词凑命中。合格 A/B/C 全部写，不只高等级。
- 跨轮先按当前方案筛选；发现历史重复才比较已保存状态快照及真实简历更新时间。任一确认变化重新全部硬筛/软筛，合格新增本批记录保留旧记录；两者都确认不变跳过，无法比较或无快照待核验不重复推荐。查看/推荐/列表刷新时间不冒充简历更新时间；新批次不是重新推荐理由，不额外追踪全部历史候选人。
- 生成 3～6 组岗位/本人动作/相邻职位/结果指标/场景/公司词，含同义词和英文缩写，记录使用条件、预期方向与误判线索。先高精度，再同义/动作、相邻岗位/场景/公司，最后非硬性标签；不足自主扩召回及轮次，不放宽硬边界。新增复杂读取方案或读取歧义先解释并确认。

## 正常工作量、台账与恢复

默认详情有效核验 100 名独立候选人，上限 300；达到 100 可结束，不必无条件到 300，不因找到 5 名合格者早停，不保证推荐人数。“试运行”按正常规模、保持 Skill/硬筛看效果；仅另行明确授权小规模可缩量且标小规模，显式只读不缩量。

“找 N 份简历”默认有效详情核验 N 人，不是推荐 N 人，首次方案说明；明确“推荐 N 人”解释可核验规模与无结果保证。其他目标记录，低于正常规模、超过上限或与已确认边界冲突只澄清数量，不静默截断/扩数。

停止于目标/上限达成、真实候选池耗尽且扩展已取证、登录/页面/权限/读写阻塞。未达目标部分完成；未完整扩展取证不称人才库耗尽。

台账至少保存岗位、Prompt 版本、固定 batch_id、查询/轮次、稳定候选人标识、阶段、已查/未查、证据/淘汰原因、状态快照/真实更新时间、待写/已写/回读状态、下一恢复位置。保存在本轮授权资源或安全的本地运行时数据，禁止将完整候选人材料、个人数据或凭证保存进 Skill（无论公开或私有）。本地临时进度使用 Skill 目录外的安全临时位置，不扩大既有授权范围，不声称未实现持久存储。

分别计数：原始或去重列表召回、本轮独立列表候选人、实际打开详情、有效详情核验、材料阻塞、历史重复、锁定、硬筛淘汰、软筛零命中、合格 A/B/C、待写、已写、回读成功。有效详情=进入详情取得明确硬筛淘汰证据，或完成全部所需核验；空白/读失败/列表排除不计，同人重试只计一次。主淘汰原因可互斥，其他多标签另列，不混用推导唯一人数。

同一失败运行恢复原 batch_id/进度，明确新一轮才新批。响应失败但可能写入先回读再决定重试，未知不直接重发；有限重试，无法找到可靠跨会话台账标恢复阻塞，不猜计数。

## 长期岗位与更新

岗位配置和运行状态分离，Prompt/绑定保存可回读文档或授权元数据。岗位为“待确认/已配置可运行/更新待确认”，运行为“执行中/完成/部分完成/失败/只读完成”。再次唤醒读取最新确认版，唯一岗位且目标明确的“找一轮人/运行一轮/帮我 sourcing”授权一次正常写入运行，不重新解析 JD/补默认问题/新建资源；多岗位只问目标，缺配置只索取绑定，未决更新/权限只解阻塞项。普通后续唤醒回到已确认正常写入模式；明确持续只读则持续到变更。

“这次先按”仅本轮覆盖；明确“更新 Prompt/以后按”才持久更新。每次生成、更新或再次执行先读 [独立岗位 Prompt 契约](references/role-prompt-contract.md)，按稳定 role_id 和真实文档绑定锁定允许修改范围；多岗位且目标不明确时只问目标。读取最新版 → 定位指定改动及硬筛/软筛/召回/分级/字段联动 → 说明变更/影响/版本 → 保存可恢复旧版 → 局部更新回读。明确且无歧义不重确认未改项，模型建议或实质冲突先确认。只按真实工具支持保存版本历史；失败保留最后可验证确认版，停止半更新方案，多资源不宣称原子成功。包括岗位通用项在内的更新只写目标 Prompt，不改通用 Skill、其他岗位、人工内容及旧批次；运行使用该岗位已确认快照，不重新以基础默认覆盖。

## 结果写入闸门与依赖

使用 `browser` skill 完成招聘系统交互，使用 `lark-doc` skill 完成岗位/候选人 Docx 读取、创建、原生表格局部插入及回读。按当前能力规则检查登录、权限、字段与写入支持，不穿透调用内部脚本/API；本包不提供凭证、招聘接口或已验证自动化。缺能力合理停止，不伪造完成、不绕登录/验证码/权限。

只写全部硬筛和软筛门槛通过的合格者；只局部新增本轮区块，不覆盖/删除人工或旧批内容。每轮复用同岗位结果文档，开始筛选候选人前新增顶部批次状态行（整行黄色填充、黑字，样式验收按结果参考），旧批保留；不增加任何批次字段列。状态计数、同等级精确时间排序及高风险小批即时回读按结果参考执行。Docx 不声称原生自动排序或动态 checkbox，明确用可见 ☑/☐。字段、时间、幂等与插入验收细节只在结果参考维护。

不创建/修改/管理定时任务，不收集时间、周末、截止时间、模板 ID 或 Skill 配置模板。正式结束后可选建议使用者自行在其已支持的调度系统创建，不编造入口或声称云文档系统原生执行招聘浏览器任务。

## 完成与诊断

配置草案完成=已解析 JD、完整方案和关键缺口；资源已创建=创建获授权且岗位文档、结果 Docx/原生空表及绑定回读；只读结果已展示=真实核验诊断且明确未写、覆盖是否达标；正式完成=正常覆盖达标，合格结果实际写入回读成功。未达覆盖或回读失败部分完成。

零合格报“覆盖完成、零合格、无可写结果”，仅写授权批次汇总，不造候选人行、不声称候选人写入成功。提供真实过滤/查询、各轮召回及独立核验、前三淘汰原因、扩展/阻塞证据和必要真实匿名边界案例，区分零召回、读失败、状态/硬筛/软筛淘汰、历史不变；不合格案例不写正式表。召回优化可执行，规则放宽先确认作用范围。
