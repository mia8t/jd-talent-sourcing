## 资源与岗位配置

通过 `lark-doc` skill 读写，按其当前 XML、表格、创建/更新及权限规则执行；这里声明意图和数据协议，不固定其内部脚本或 API。

首次获授权创建独立岗位 Prompt 文档“岗位名称-skill使用者-人才sourcing方案”和独立候选人结果 Docx“岗位名称-skill使用者-候选人结果”，使用当前使用者显示名。结果文档包含固定简介/批次插入锚点及字段定义一致的原生空表。用户指定已有授权 Docx 时复用；同名先核对岗位标识、使用者、保存绑定，不覆盖/重复创建，归属不明只问资源问题。岗位改名不自动新建，变更目标需授权。

本包采用 Docx 原生表格作为结果容器，不自动创建或嵌入其他表格系统。不迁移、修改或删除已有资源；已有岗位绑定不同类型的结果资源时，先取得新 Docx 目标的明确授权，不能静默迁移。

岗位文档或授权元数据保存 role_id、岗位名/使用者/确认状态、JD 原文或来源、完整 Prompt/通用规则例外、prompt_version、初始化默认来源/实际基础版本、可恢复前版/历史引用、摘要/更新时间/确认依据、岗位文档与结果 Docx URL/token、原生表块/插入锚点及字段映射、目标/上限/默认写入模式/唤醒语义、历史流程及负责人范围、最近批次/运行状态。岗位 Prompt 正文保存全部有效标准，不以基础版本指针或其他岗位文本替代；默认来源只用于追溯。不同 role_id 的 Prompt 文档独立绑定；标准正文、变更历史和运行状态分区，旧批数据不反向修改筛选标准。仅保存实际取得的标识；新块 ID 写后重新读取，不伪造历史或链接。

## 候选人原生表字段（唯一格式定义）

以下为空字段规格，不包含任何实际人员或组织数据；运行时仅在授权结果资源内填写，严禁将填写后的表格、证据或资源链接写回技能或发布包。不因通用美化建议删字段或增加筛选。姓名与链接合并，简历关键词为 3 个明确文字词，其他多选/日期/文本以原生表文字表达，不改变判断语义。

| 可见列 | 内容及口径 |
|---|---|
| 姓名 | 真实姓名，单元格内带有效人才库详情 href，不另列裸链接 |
| 工作年限 | 单位年，可 1 位小数；采用主文/岗位确认计算口径 |
| 最近一份工作的公司背景 | 最近全职公司正式名称 |
| 最高级别/规模最大公司 | 从可核验经历选择，不无依据断言评级 |
| 简历关键词 | 3 个最相关核心关键词，不冒充通过证据 |
| 候选人等级 | A/B/C |
| 特殊标注 | 默认仅“同岗位面过”，其他留空 |
| AI 优势 | 明确符合岗位 AI 标准写 ☑，否则 ☐；可见文字，不宣称动态交互控件 |
| 推荐时间 | 本次推荐的北京时间 YYYY-MM-DD HH时，固定文字不含分钟 |
| 岗位配置版本 | 本轮最新确认版本 |
| 候选人唯一标识 | 平台稳定 ID 优先，否则已核实规范详情链接，不能只用姓名 |
| 简历真实更新时间 | 页面真实值原始精度；读不到未知，不用推荐时间替代 |
| 状态快照 | 已核验锁定、意向、相关历史状态及来源/时间 |
| 筛选证据 | 硬筛、软筛、加分依据和风险，不只关键词 |

字段文字一律来自详情页及可核验材料。非中文简历的核心信息按原意译为中文填写，公司名保留正式原写法，不自行改译、缩写或另造中文译名。

推荐精确时间不作为隐藏排序控件：真实精确推荐 timestamp 保存在授权运行元数据/台账，首次形成推荐记录时固定、失败重试沿用。批内先 A/B/C，再同等级按精确推荐时间排序；升降方向沿用已确认岗位配置，当前岗位未配置排序方向时只澄清此操作参数，不改筛选标准。时间未知不得伪造排序时间，说明阻塞。文档无原生自动排序，靠写前排序及安全局部插入保持顺序。

姓名 XML 意图为 `<td align="left"><a href="实际核实的详情URL">真实姓名</a></td>`；文本/属性按 XML 转义。绿色姓名仅工具实际支持且回读/预览验证才选用，不用背景替代，不阻塞写入。链接必须来自真实可访问详情，不根据 ID 猜 URL；访问失败说明，不把 href 存在称访问验证成功。

## 批次版式与幂等

每轮开始用当前准确时间生成一次精确 batch_id（岗位标识+北京时间精确时间+唯一后缀），保存真实开始时间及内部 batch_id→文档/本批表/状态文本块 ID 映射。失败沿用，明确新一轮才新 ID；同小时不同轮内部 ID 不同，不用小时去重，不在候选人行增加任何批次字段。

在开始筛选候选人前、写入授权范围内，于固定锚点后插入本批状态行及原生空表，置于全部旧批之上；只读运行不写远程行，仅对话展示。固定格式为“筛选批次（北京时间YYYY年MM月DD日HH时） X份/Y份”，开始为 0份/0份，小时来自真实本轮开始时间且固定。本批状态行必须跨全部当前列合并（目前 14 列），整行黄色填充、黑色批次文字，之后列头及候选人行不采用黄色填充。黄色填充使用合并单元格 background-color="yellow"，黑字使用当前平台支持的黑色/默认黑色并验证；不是黄色字体或仅文字高亮。这里指定平台黄色，不声称精确像素色值已测试。若无法可靠创建合并行或独立局部更新其状态文本，紧前备用行只有在当前 lark-doc 能力能达到与本表等宽的整行黄色背景、黑字且回读验证通过时才可用；否则报告样式阻塞，不能用普通无底色文本、局部文字高亮或黄色字体冒充完成。两者均不得增加批次列，内部精确 ID 只存在绑定/台账，不显示为新增列。

X=本轮有效详情核验的独立简历数，严格使用主文真实计数定义；包括已取得明确硬筛淘汰证据的详情，不意味着每份已全项核验。列表召回/列表排除、空白/读取失败、同人重试均不计。Y=本轮新增实际写入且回读成功的独立候选人记录数；已有记录、失败、待写及未知写入状态不计。恢复已存在的本轮新增记录仅经回读确认后计一次，不作再次新增。

每个小批写入回读后，或筛选计数变化的检查点，按真实台账只局部更新本批状态文本，保留整行黄色底色、黑字、合并范围、列宽和其他完整样式，并再次回读文字与样式；不能用纯文本替换丢失样式。固定行外另说明执行中/部分完成/失败、短路与未查项、未知写入数；不得把 X 称全部完整核验、把 Y 当合格数或写接口成功数。状态更新失败保留可验证旧值，立即对话报告真实 X/Y、文档状态陈旧及恢复位置，不称状态已同步。

合并行使用 colspan=14，仅起始单元格输出，覆盖格省略；不是 rowspan，也不是批次字段。候选人完整字段仍按上表，旧批及人工内容不动。零合格显示实际 X份/0份，可保留空表列头但绝不造候选人行。

候选人同批幂等键=role_id+batch_id+候选人 ID；同时检查姓名单元格实际 href，已核实同 ID/规范 href 的不同投递应识别同人，不按链接显示文字去重。保存 ID 与 href 映射，身份矛盾待核验不造重复记录。跨批变化资格按主文，不因批次不同重复推荐。

写前读目标文档/本轮队列和内部块映射。失败响应未知先在映射到的本批区块回读候选人 ID/href，不直接重发，不要求行内 batch_id。旧批全部保留，人工修改不可覆盖；同批恢复只新增缺失合格者，不重建旧表。无法安全在当前批表按等级及精确时间局部插入时停止说明能力缺口，不能靠整表/整篇替换实现排序。

合格即写或本轮统一写均保留；风险较高时优先小批写入且每小批立即回读，保存已确认记录、待写队列、精确时间及断点后才推进下一小批。必要表内插行能力不足时停止，不能用整表覆盖规避小批回读。空结果只更新本批状态/汇总，候选人写入数为零。

## 原生表表达与写入验收

通过 `lark-doc` skill 核实当前 XML、合并及局部更新能力。仅在目标工具支持时使用 colspan 合并及局部字符串/文本块更新，不能把表格整块替换当作单元格局部修改。合并状态行宜在 thead 第一行用一个跨 14 列的 td，第二行为 th 列头，tbody 为候选人行；只输出合并起始格。先取得可独立编辑的状态文本块 ID；若当前工具只能整表替换，仅考虑满足上述等宽整行黄色背景验收的备用行，否则停止并报告样式/局部更新阻塞。备用行的局部块更新必须保留完整背景、黑字及宽度样式，更新后重新取 ID；行内 str_replace 仅在旧文本全文唯一且确认目标时用，同小时同数值多批不能全文误替换。表内状态文本没有安全局部更新能力时不采用合并方案，绝不整表覆盖。表列宽用紧跟 table 的 colgroup/col；每个 th/td 显式 align（紧凑值居中、姓名/长说明左对齐，列内一致），不使用不支持的 table header-row/header-col/col-widths。不要 Markdown 管道表作为云端写入内容；上方字段清单仅是 Skill 本地规格。

执行时需加载 lark-doc 当前要求参考，实测云文档创建、顶部插入、原生表写入及回读；不能把静态语法支持说成远程成功，也不能声称已验证动态交互 checkbox。

1. 获授权后回读绑定、字段/原生空表、固定简介与插入锚点。读取目录定位，再局部获取锚点 ID、顶部旧批及所需旧表完整内容；旧内容/人工字段保留可比较快照，节选不是完整旧表。
2. 筛选前先插入并回读 0份/0份 状态行，之后按已确认写入方式将合格队列按等级/精确时间局部插入本批表；风险较高使用上述小批即时回读协议，不逐人再索授权。
3. 使用 lark-doc 受支持局部插入，在固定锚点后把新批置于旧批上方；没有可靠锚点或顶部插入能力就停止，不用末尾 append 冒充顶部，不整篇 overwrite、不移动重写旧批。
4. 检查退出状态、ok、实际 result/warnings；partial_success 或字段降级不当全成功。插入后重新读取新 block ID 与批次整表，必要按表 ID 读取全表，不能只看命中行节选。
5. 使用 lark-doc fetch 的 full 详情读取本批整表，检查实际合并起始格 background-color 为黄色（平台可能规范化为颜色值）、colspan 覆盖全部当前列、文字为黑色/默认黑色、列头及候选人行未黄色填充。读取面若不含合并/背景/字色或无法确认等宽整行效果，补充当前受支持的视觉核验；仍无法确认则标样式待验证/阻塞，不能仅凭表格写入成功称样式成功。每次小批状态更新后重做该验收，禁止整表覆盖补样式。
6. 核对目标 Docx、姓名及实际 href/访问结果、候选人 ID、内部 batch_id 与块映射、状态行中文北京时间及真实 X/Y、批次新先旧后、批内等级/精确时间顺序、全部字段/年限/3 词/AI ☑☐/版本/证据/特殊标注；比较原旧块内容、链接、人工反馈未变。文档确有无关人工同时修改时停止后续写入，说明差异，不自行恢复或覆盖人工改动。
7. 记录待写/已写/回读成功及未知状态分别计数；失败报告已完成数、未完成/未知、具体步骤和恢复位置，仅有限重试。

## 简洁输出信息结构

- **补缺**：岗位目标/已有方案、默认采用/已回答、仅关键缺口及选项影响、真实冲突。
- **最终方案/Prompt**：按下方“最终确认展示”先标准、后执行，保留主文要求的完整方案及真实绑定；未绑定标未绑定，已有明确授权不重复询问。
- **更新回执**：旧→新版本、指定和联动修改、保持不变、仅本轮/以后、历史保存与回读、当前可执行版、未完成项。
- **再次启动**：按岗位最新确认方案、复用结果 Docx、目标有效核验人数、合格本批写入回读，随后真实执行，不只说已启动。
- **失败/零结果/完成**：真实状态、岗位/版本/文档链接、批次及正常/正常试运行/授权小规模/只读范围、目标/独立召回/打开详情/有效核验/阻塞、淘汰/重复、合格 A/B/C、已写/回读、字段/顺序/旧内容验收、具体不足和恢复位置。零结果诊断及完成判定按主文，不重复维护另一口径；说明岗位仍可唤醒。

## 最终确认展示（仅展示规范）

标准确认在前、执行说明在后。先用一句话归纳本岗位业务目标及候选人个人贡献画像，再展示下面三张独立矩阵，体现对用户/JD/默认标准的理解，而非逐步执行长文。对话可用 Markdown 表格；如写云文档，使用 lark-doc 当前原生表表达规则。本节不新增业务标准、字段或检索数量。

先列岗位/版本/目标，再将以下同结构矩阵分别置于“通用硬筛 G”“个性化硬筛 H”“软筛 S 与加分”三个独立小节，每项独立一行；不得合并成一张未分区长表或一大段正文。具体完整 Prompt 结构与隔离约束按主文引用的独立岗位 Prompt 契约执行。

|---|---|---|---|---|
| <维度/规则编号> | <用户标准的准确归纳，不泛化为职位标签> | <已明确性质；未决标待确认> | <本项要求的证据；按现有规则处理缺失> | <用户已回答/JD 原文/Skill 默认/系统建议及确认状态> |

### 5. 完整执行 Prompt（操作段，置于确认展示末段）

附完整 Prompt 的执行部分：筛选与检索、历史范围、真实资源绑定、工作量、授权边界、写入/批次/回读、计数和故障恢复等。前面的分区标准及分级表与本操作段共同构成同一份完整岗位 Prompt，必须一并保存，不把操作段单独作为可交接 Prompt。可在该文档内部引用稳定规则编号，但所有规则正文必须已完整展开，不依赖聊天历史、Skill 默认或另一个文档。展示与保存的有效条件保持一致，未绑定/待验证/待确认如实标记。

末尾仅给简短选择：**标准正确保存暂不执行 / 保存并执行 / 修改 x 项**。说明前者确认标准及在明确目标和范围内保存，不授权寻访；后者包含保存与本轮执行，只按既有授权闸门推进；修改只影响指定项。保存到远程文档也属于写入，需要对应目标及保存授权，不能把“标准正确”单独当远程保存或执行授权。资源/执行范围有真实缺口时只补问该缺口；已有明确授权不重复索要。
